Which agent touched production?

Coding agents open pull requests. Agent Gate comments on the request: who did it, which production paths moved, how to roll back, and the one policy edit that revokes that agent.

Review a sample pull request Six-line install
Runs on
The repository’s GitHub Actions minutes. A surge does not bill you.
Needs
A policy file in the repo. AWS, a domain, and a model key come later.
Blocks merge
Only if you set fail-on-risk: high. Otherwise it is a comment.

Install

Replace OWNER with your GitHub username after you publish this repo. Checkout has to come first so the policy file is on disk.

- uses: OWNER/agent-gate@v1
  with:
    fail-on-risk: never
    policy-path: .agent-gate/policy.yaml
    api-key: ${{ secrets.BLAST_RADIUS_API_KEY }}
    model: ${{ vars.BLAST_RADIUS_MODEL }}

Leave api-key unset and the comment is still posted. The key only adds a short summary.

The kill switch is a file

Agents you trust get an allow list. Production paths you care about get a risk. Deny removes an agent in the next pull request.
