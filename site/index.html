Agent Gate, sold as one comment

One comment. Not five security tools.

VETO comments on the pull request. It says who opened it, whether production changed, whether a secret or an old package slipped in, and what to do next.

In this check What you see
Secrets The file and the kind of secret. The value is not copied into the comment.
Packages A known advisory for a dependency version, with the version to upgrade to.
Dangerous code A shell turned on, code run from text, TLS checks turned off, or a database query built by joining input into the SQL.
Infrastructure and containers An open network rule, public storage, a privileged container, or an image tagged latest.
Tests Application code changed and the diff has no test file. This is not a coverage percentage.
Not in this check A running application, and a cloud account. StackHawk, Prisma, Orca, and Wiz need those. Dependabot still opens its own pull requests. VETO reads the versions in the diff.

Two pieces. Critical findings fail the job. In the repository settings, require the gate check before merge.

1. Add this workflow

Save it as .github/workflows/agent-gate.yml.

name: Agent Gate
on:
  pull_request:
permissions:
  contents: read
  pull-requests: write
jobs:
  gate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: Thiru-Cloud-Architect/agent-pr-gate-app@v1

2. Say which paths are production

Copy the sample rules to .agent-gate/policy.yaml. In this demo, production means infra/prod/** and charts/payments/**. cursor[bot] may edit docs, and may not edit production. dependabot[bot] may edit package files.
